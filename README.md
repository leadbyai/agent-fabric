# LeadByAI Agent Fabric — Herdr gateway

Vendor-neutral, authenticated AG-UI gateway for **existing** Herdr-managed
coding agents. Agent Fabric can discover multiple Herdr sessions belonging to
one Unix user and address an individual agent by its live pane ID.

## Release status

`v0.5.0` is a **staging release**. It was tested with simulated Herdr agents;
it has not yet been validated against a production Herdr/OpenBot installation.
The installer defaults to `127.0.0.1:8766` so it can run beside an existing
bridge without changing its listening port or shutting it down.

It does **not** create, start, stop, or resume Herdr sessions or agent
processes. A stopped session is listed as offline until the owner starts it.

## HTTP endpoints

| Endpoint | Purpose | Authentication |
| --- | --- | --- |
| `GET /health` | Process health | None |
| `GET /agents` | Discover recognized agents across configured sessions | Bearer token |
| `GET /attention` | List blocked agents and offline sessions | Bearer token |
| `POST /sessions/<session>/agents/<pane-id>/ag-ui` | Send AG-UI request to one existing agent | Bearer token |
| `GET /sessions/<session>/agents/<pane-id>/model` | The agent's provider, offered models and efforts, and current model ([docs/model-control.md](docs/model-control.md)) | Bearer token (not discovery) |
| `PUT /sessions/<session>/agents/<pane-id>/model` | Switch model and effort **for this session only** | Bearer token (not discovery) |
| `POST /ag-ui` | Legacy single-agent entry point when configured | Bearer token |
| `GET /agent` | Legacy target status when configured | Bearer token |

Small inline file attachments and OpenBot's textual attachment reconstruction
are supported. Dynamic routes stage files only beneath configured allowed
working-directory roots. Larger files can be shared using external file links;
the bridge does not fetch arbitrary attachment URLs.

## Installing

Requirements: Linux with systemd, Python 3, curl, and an installed Herdr CLI
for the selected Unix account. The selected Herdr sessions must belong to
that same account.

The installer is idempotent for the service it owns and stores its bearer
credential in a root-owned file supplied to the service via systemd
`LoadCredential`. It does not overwrite an unmanaged service and backs up its
own previous Python bridge before updating.

From a reviewed local source checkout, install into a separate port:

```bash
sudo bash ./install.sh --source-dir "$PWD" --user agentuser \
  --sessions Main,Review --roots /home/agentuser/work --port 8766
```

When this version is published, use the **commit-pinned** installer download
URL rather than a moving branch. The installer verifies `bridge.py` against
its embedded SHA-256 checksum. Change the example user, sessions and upload
roots to match the destination host.

```bash
curl -fsSL https://raw.githubusercontent.com/leadbyai/agent-fabric/COMMIT_SHA/install.sh | sudo bash -s -- --user agentuser --sessions Main,Review --roots /home/agentuser/work --port 8766
```

The `COMMIT_SHA` placeholder is deliberately not executable as-is. Use the
exact published commit SHA supplied with the release.

The installer does **not** configure public DNS or Cloudflare credentials.
Once locally validated, publish only the localhost bridge through an
authenticated HTTPS proxy/tunnel. Do not expose Herdr's socket or terminal
control API to the Internet.

Optional backwards-compatible legacy route:

```bash
sudo bash ./install.sh --source-dir "$PWD" --user agentuser \
  --sessions Main --roots /home/agentuser/work --legacy-target demo \
  --legacy-workdir /home/agentuser/work/demo \
  --token-file /home/agentuser/.existing-bridge-token --port 8766
```

Inspect the staging service:

```bash
curl -fsS http://127.0.0.1:8766/health
sudo systemctl status openbot-herdr-gateway.service --no-pager
```

### Tailscale bind and hash-only, per-agent tokens (optional)
Without these options the install is exactly as above (loopback bind, one bridge-wide token file).
- `--bind <tailscale-ip>`: bind to this host's own 100.64.0.0/10 address instead of 127.0.0.1, for a
  client that reaches the host over Tailscale. Wildcard and public addresses are refused.
- `--route-token-sha256 <session>/<pane>=<sha256>` (repeatable): one token per agent. It can sit **beside** a
  bridge-wide credential (`--token-file` or `--token-sha256`): the bridge-wide token still reaches every route, and each
  route token reaches only its own. Route tokens alone replace the bridge-wide token; the installer refuses that
  while a bridge token file exists, unless `--route-tokens-only` is passed.
  Per agent: A token reaches
  only its own agent route; discovery, `/requests` and `/attention` show only that agent; the legacy
  `/ag-ui` and `/agent` routes need a bridge-wide credential. The gateway stores only hashes; the token
  is generated by the client (for example inside OpenBot's encrypted vault).
- `--token-sha256 <sha256>`: one bridge-wide token, stored as a hash only.
- `--expect-bridge-sha256 <sha256>` with `--source-dir`: install a reviewed `bridge.py` that is not the
  pinned release, after checking its hash.

### Automatic sessions and a discovery-only credential (optional)
- `--sessions auto`: serve every *running* Herdr session (from `herdr session list --json`, cached 30 s)
  instead of a fixed list, so new sessions need no configuration. A failed session listing answers 503,
  never an empty roster.
- `--deny-sessions NAME[,NAME]`: never served or routed, in either mode. With `auto`, the bridge-wide token
  reaches every served session, so keep this list strict.
- `--discovery-token-sha256 <sha256>`: an extra, hash-only credential that can `GET /agents` and
  `GET /attention` only. Every POST, `/requests` and `/agent` is 404 for it. It is meant for an automatic
  reconciler that must never be able to prompt an agent. It must differ from every other token.
- With `--sessions auto` or `--discovery-token-sha256`, also pass `--verify-token-file PATH` (a token the
  new gateway must accept, e.g. the discovery token). After the restart the installer requires
  `GET /agents` to answer 200 with a session list, not only `/health`; otherwise it restores its backups.
- `/agents` reports each agent's Herdr kind (`agent`, e.g. `claude`, `hermes`) and `session_mode`.

`--backend both` runs this install and then `install-hermes.sh` with the `--hermes-*` options
(see `docs/hermes-backend.md`).

## Safety and rollout

- No agent input is submitted while Herdr marks that agent `working` or `blocked`.
- With the bounded queue on (`OPENBOT_BRIDGE_BUSY_WAIT_SECONDS` > 0), a message to an agent that is
  waiting on a question (`blocked`) is **held, not refused**. OpenBot shows "<agent> is waiting for an
  answer on its own screen. Your message goes in once it's answered." in place of "Thinking". It adds the
  question itself only with `OPENBOT_BRIDGE_SHOW_QUESTION_TEXT=1`, which is off by default because the
  gateway can't tell a Bot's owner from someone it's shared with. Set it only where every requester may
  see the operator's questions. The message goes in once the
  question is answered on the agent's own screen and the agent is idle again. The gateway never answers
  the question and never sends keys to the pane. Limits: `OPENBOT_BRIDGE_QUESTION_HOLD_SECONDS`
  (default 1800, shared by every message held for one question; `0` restores the old refusal) and
  `OPENBOT_BRIDGE_QUESTION_HOLD_MAX` (default 3 messages per agent). Beyond either limit, the message is
  refused with a reason and is not submitted. A question asked mid-turn is shown the same way, and the
  reply still arrives once it is answered, within the same hold limit.
- A Claude Code agent that is signed out ("Login expired · Please run /login" as the last thing on its
  screen) is not prompted. The run fails at once with "<agent> is signed out". If the CLI signs out
  after the message was submitted, the run fails as soon as that shows, without waiting out the
  recovery window.
- **Reply fallback (Claude Code panes).** The gateway first reads the reply the agent marked on its screen. If
  that can't be read (the pane was resized after the reply, which truncates the screen history; or the agent
  used another request's marker, or none), it reads the reply from the agent's own session transcript: the file
  named by that pane's own process (its `CLAUDE_CONFIG_DIR` and Claude Code's `sessions/<pid>.json`), never a
  search. It takes the last assistant text of the turn that began with this request's id, only once that turn
  has ended, capped like a marked reply. The ledger row records `reply_source` (`marker` or `transcript`), and
  the journal logs `reply_source=transcript`. Codex panes and `--machine` gateways keep marker-only behaviour.
  `OPENBOT_BRIDGE_TRANSCRIPT_FALLBACK=0` turns it off.
- Every failed run is journaled (`run failed request=… pilot=… submitted=… reason=…`). When a submitted reply
  still can't be fetched, OpenBot shows that the agent got the message, that the reply is on the agent's own
  screen in Herdr, and that it won't be sent again.
- Requests to unknown agent panes and stopped sessions are rejected.
- A per-agent lock prevents two concurrent OpenBot requests targeting one pane.
- Failed or ambiguous CLI submissions are **never retried automatically**.
- The gateway stays localhost-only; its bearer token is never logged.
- The existing single-target bridge need not be removed or restarted.

Run offline tests before deployment:

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh
python3 -m py_compile bridge.py
```

**Not yet implemented:** automatic OpenBot Bot creation/synchronization or
native push notifications. `GET /agents` and `GET /attention` expose the
necessary status information, but OpenBot's authenticated registration and
notification interfaces must be integrated and verified separately. A
staging gateway alone does not populate the OpenBot sidebar.

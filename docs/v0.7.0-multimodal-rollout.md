# Agent Fabric v0.7.0 — reliable instructions and screenshots

Status: **release candidate; offline-tested, not deployed**. Do not describe the
feature as live until all production acceptance checks pass.

## What changes

- No 4,000-character prompt limit. Text short enough for the Herdr CLI travels
  normally; longer text travels in a private `full-user-instructions.txt` under
  the selected agent's `.openbot-inbox/<run-marker>/`. The agent is instructed to
  read the whole file. Inputs remain bounded by the 64 MiB HTTP request limit.
- User screenshots reach the correct Herdr pane as binary PNG/JPEG/WebP from the
  AG-UI inline DataSource. OpenBot 1.0.2 already resolves `/api/attachments/ID`
  URL references into base64 DataSources before forwarding to remote agents.
- Agents can return screenshots: write the image to
  `.openbot-outbox/<run-marker>/screen.png` and put the line
  `OPENBOT_IMAGE: screen.png` inside the usual correlated response markers.
  The gateway verifies size/type/path and (by default) embeds a bounded image
  within the authenticated OpenBot message. The reply uses standard AG-UI
  assistant **text**, carrying Markdown's `data:image` representation; it is
  stored with the conversation and requires no public artifact path.
- The agent queue, run ledger, retry protection, and Herdr sessions are unchanged.

## Privacy, message size, and retention

**Default `inline` mode:** screenshot bytes travel as data images in the
assistant's normal text reply. No new public URL is created and OpenBot retains
the images under its existing authenticated conversation access. Images must be
2 MiB or smaller each, with a 4 MiB total bound on returned images per answer.
If larger, the gateway fails explicitly and the agent must create a smaller
JPEG/WebP screenshot. Streamdown supports data images in Markdown by default,
but the actual deployed OpenBot renderer must pass a browser smoke test.

This design intentionally stores a base64 representation in the assistant reply
and therefore the OpenBot database. It is suitable for occasional screenshots,
**not** a high-volume image archive. The OpenBot server customization must strip
these large data URI segments from *history forwarded back to agents*, while
leaving the saved conversation intact. A native binary attachment row can replace
this representation in a later upstream-compatible revision if volume grows.

**Optional `signed_url` mode** exists only if someone deliberately selects it.
It serves capability URLs with 256-bit randomness, expiring after 30 days by
default, under `/var/lib/openbot-herdr-gateway/artifacts`. Anyone possessing a
particular URL can view it. Do not enable this mode for client screenshots
without an explicit privacy review.

## Pre-release validation

On a development checkout with Python 3.14 or compatible Python 3:

```bash
python3 -m unittest discover -s tests -p 'test_bridge.py' -q
python3 -m py_compile bridge.py request_ledger.py
sha256sum bridge.py request_ledger.py
```

Test coverage includes long Unicode instructions, binary screenshot delivery
to one pane and not another, agent screenshot retrieval, symlink refusal,
idempotent run replay, blocked and queued agents, and response correlation.
These are protocol simulations; the browser preview and Cloudflare route still
require a real production test.

## Canary deployment — preserve running sessions

1. Merge a reviewed PR into `leadbyai/agent-fabric` and publish a pinned release
   tag **after** refreshing hashes in `install.sh`; do not use a floating `main`
   download in production.
2. Back up `/opt/openbot-herdr-bridge`,
   `/etc/openbot-herdr-bridge/config.env`, its token **without printing it**, and
   `/var/lib/openbot-herdr-gateway/requests.sqlite3` before changing the service.
3. On `lbai-admin`, use the existing `ubuntu` identity and sessions `lbai,3WM`.
   Supply the same upload roots and wait/recovery values that are in the current
   config. Keep the default `--artifact-mode inline`.
4. On `lbai-arcaiva`, use `arcaiva-pilot`, session `Arcaiva-Claude`, same
   `inline` mode.
5. On `lbai-ci1`, use `ubuntu`, session `careintel`, same `inline` mode.
6. The installer preserves the existing bearer token, Herdr sessions and
   agent processes. It makes code/config backups and restores them if its local
   health check fails. It restarts **only** `openbot-herdr-gateway.service`.
7. No Cloudflare rule change is needed for `inline` mode. Preserve every
   existing authorization requirement on the gateway endpoints.

Example template, **not copy/paste ready** until roots and current options
are verified:

```bash
sudo bash install.sh \
  --user ubuntu \
  --sessions lbai,3WM \
  --roots /home/ubuntu/projects:/home/ubuntu/work \
  --port 8766 --busy-wait-seconds 600 --recovery-seconds 600 \
  --artifact-mode inline
```

Never send the contents of `bridge.token` to a chat, browser console, or CI log.

## Production acceptance — all mandatory

For each selected pilot Bot:

1. Send `Reply exactly: READY` through OpenBot. Confirm exact response and
   retained text after refresh.
2. Paste a long but legitimate 10,000–20,000-character instruction. Confirm no
   HTTP 400 and that the agent can quote the final line (proves no truncation).
3. Paste/upload a screenshot containing a unique word and ask the agent to
   report that word. Confirm it read the file. **This also verifies OpenBot's
   `url`→`data` attachment handoff in the deployed version.**
4. Ask the agent to create and return a small PNG screenshot. Confirm it
   appears inline, remains after a refresh and the browser does not fetch any
   unauthenticated `/artifacts` URL.
5. While that Bot works, submit B immediately after A in the same conversation.
   Confirm both replies arrive, A then B, and neither disappears.
6. Repeat one identical `runId` and confirm it does **not** resubmit the Herdr
   prompt; check ledger state and original reply are retained.
7. Refresh OpenBot and confirm the screenshot/link and both responses remain.
8. Confirm no secrets or user message bodies appear in the gateway journal.

If any check fails, stop the rollout, keep the last healthy gateway in place,
and capture **redacted** HTTP status, gateway journal and Agent Fabric request
IDs. Do not modify/restart Herdr sessions as a diagnostic shortcut.

## Longer-term native binary attachment path

Inline images solve the immediate secure transport without public URLs, but
they do add base64 to stored assistant text. For high-volume screenshots,
extend `leadbyai/openbot-custom` so remote-agent images are persisted as native
binary attachment rows and fetched under OpenBot's channel authorization.
Keep that extension in the overlay/fork, with upstream pinned and rebased,
rather than changing a running container by hand.

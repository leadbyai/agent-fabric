# Agent Fabric v0.6.1 — completion correlation and disconnected clients

This is a narrow corrective release for the v0.6.0 Arcaiva canary. No Herdr
sessions, agent processes, gateway bearer tokens, or Cloudflare routes change.

## Incident observed on Arcaiva

Two requests were sent to the Arcaiva Demo pane. The v0.6.0 ledger showed
the first run as `uncertain` (no reply), then the second as `finished` four
seconds later. This demonstrates that the first run was no longer protected
by its pane lock, not that its work was definitively lost. The agent also
reported running the test's `sleep 30` in the background; that is not a
reliable way to hold the Herdr agent's status in `working`.

## Changes

- If `herdr agent prompt --wait` returns before the unique reply markers
  are visible, continue to poll `agent read` for up to the configured
  `--recovery-seconds`. The per-pane lock remains held throughout, so another
  gateway request cannot leapfrog this still-unconfirmed response.
- If the browser disconnects **after** the request is reserved for Herdr
  submission, continue processing it to a correlated reply and store the
  result in the owner-only ledger. The client can retry the same run ID or
  inspect `GET /requests/<id>` without sending the prompt again.
- If the browser disconnects **before** submission while queued, no prompt
  is sent; the pending request remains non-durable (see issue #3).
- If correlation still fails at the recovery deadline, the ledger marks the
  request `uncertain` and tells the client to inspect Herdr. It does not
  re-submit automatically. This release does not guarantee recovery of an
  existing v0.6.0 `uncertain` request or restore an already-aborted OpenBot UI
  stream.

## Canary procedure

1. Preserve the existing Arcaiva gateway configuration and token. Install
   the immutable `v0.6.1` tag with the same `--user`, `--sessions`, `--roots`,
   `--legacy-target`, `--legacy-workdir`, port and 600-second wait settings.
2. Test one normal OpenBot request to Arcaiva Demo and verify the result.
3. For concurrency, use **two distinct OpenBot conversations** targeting the
   same pane. In conversation A, ask the agent to execute a foreground command
   such as `sleep 20` and wait for the command to exit before its final reply.
   While A is still visibly `working`, submit B in the second conversation.
4. Confirm both runs finish, and B's prompt starts **after** A's correlated
   reply. Do not treat a background shell process or two messages in one
   OpenBot conversation as a valid serialization test.
5. If a run is `uncertain`, inspect the Herdr transcript and the ledger first;
   do not blindly resend the prompt. Delay upgrading `lbai-admin` until the
   Arcaiva canary passes.

The installer verifies the bridge and ledger SHA256 hashes, backs up existing
code/config/unit, and attempts rollback if the health check fails. A service
restart briefly interrupts the gateway, but Herdr sessions are untouched.
